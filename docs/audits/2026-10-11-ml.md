# ML section audit — 11 October 2026

Baseline: `abd4b97ad27c9b2c95a8409a49b018fd9a5311fe` in `ylnhari/interview-prep`.
Scope: 15 chapters, 125 lessons and 45 practices (170 sections). Read-only remote review evaluated library first, every other core module in filename order, then the public pack. The implementation is a late generic prose override.

## Review method and limits

The same reviewer performed an editorial pass over the effective public bodies, continuations and worked practice answers, then a technical pass over definitions, numerical examples, executable-reference code by inspection, and related prompt/answer contracts. These are two passes, not independent reviewers. No sampled section is presented as full coverage: every assigned section ID appears below. This ledger records findings, not a claim that every statement is proven correct.

All section-level internal links in assigned string fields resolved against the effective catalog. Resource descriptions and destinations were inspected; selected primary sources were fetched to resolve claims. A complete HTTP sweep of external URLs, video playback, account requirements, browser rendering, SVG geometry, keyboard behavior and actual Python execution were not performed by this reviewer. The coordinating release pass owns final UI and code execution checks. Existing correctly taught content was retained.

## Evidenced corrections

- **M1, mot-0:** A serialized quiz object appeared inside the visible Health check glossary term. Remove it, restoring Health check/liveness/readiness terminology. The original quiz object and progress mapping remain unchanged.
- **M2, mot-f5:** The body instructed an inference-only timeout and explicitly rejected a whole-request timeout, then recommended an end-to-end deadline. Resolve that conflict by explaining a request deadline propagated into stage budgets. [AWS timeout/retry guidance](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/).
- **M3, mot-f8:** Counter definition omitted process resets. State that a counter increases between resets and can reset on restart. [Prometheus metric types](https://prometheus.io/docs/concepts/metric_types/).
- **M4, cm-f2:** Convexity was presented as an unconditional gradient-descent guarantee. Add optimizer/step assumptions and the unregularized separable-data case with no finite minimizer; illustrate the strictly positive finite-margin logistic loss. [Soudry et al., separable logistic optimization](https://arxiv.org/abs/1710.10345).
- **M5, mfe-f6:** Temperature was described as inference-only while the paragraph also named distillation. Explain its student-training use; qualify the zero-temperature limit for tied maxima. [Hinton et al., distillation](https://arxiv.org/html/1503.02531v1).
- **M6, dle-f2:** The body conflated backpropagation with parameter updates while the continuation separated them. State forward, loss, gradients and optimizer updates separately. [PyTorch optimization tutorial](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html).
- **M7, dle-f5:** The body promised an accuracy-for-calibration bargain from label smoothing while the continuation correctly called its effects task-dependent. Align the body with that qualification. [Müller et al., label smoothing analysis](https://arxiv.org/abs/1906.02629).
- **M8, uq-4:** DeepAR direct-quantile wording conflicted with uq-f1. Explain likelihood parameters, trajectory sampling and derived quantiles. Replace assumption-free residual bootstrap and identical-drift-behavior claims with representative-error/dependence requirements; distinguish parametric shape assumptions from conformal exchangeability. [DeepAR algorithm](https://docs.aws.amazon.com/sagemaker/latest/dg/deepar_how-it-works.html), [forecast bootstrap](https://otexts.com/fpp3/advanced.html#bootstrapping-and-bagging), [conformal tutorial](https://arxiv.org/abs/2107.07511).
- **M9, ct-2:** A fixed token bucket was listed as a feedback controller despite ct-1 explaining that it is not automatically feedback. Specify adaptive refill based on measured outcomes; original token-bucket operation remains elsewhere.
- **M10, mlp-a2:** Remove a duplicated nested expansion of precision-recall AUC in the worked answer.
- **M11, rl-a1:** An independent learning audit found that the prompt asked for three decisions without supplying them. Add concrete temperature prediction, one-step message choice and courier-capacity decisions; provide classifications, baselines, evaluation assumptions and conditions that change the classification. No quiz or section identity changes.


Further independent cross-review and parent technical findings:

[PyTorch clipping](https://docs.pytorch.org/docs/stable/generated/torch.nn.utils.clip_grad_norm_.html), [Adam update](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adam.html).
- **M18, uq-a1:** Restore quantile-regression mechanism and when-to-choose comparison, preserving the four-sentence prompt and conformal assumptions.
- **M19, or-a0:** Supply requested modeling libraries, engines, problem categories, four metaheuristics and a bound-versus-incumbent optimality-gap definition in the worked reference.
- **M20, or-a1:** Only an approved negotiable workload target can be softened; safety/legal/physical capacity stays hard.
- **PT02, ro-a2:** Alert time does not determine prediction cohort maturity. Distinguish a newly reported mature older cohort, provisional labels, proxies and monitoring artifacts.
- **PT07, mot-f5:** Propagated deadlines do not prove GPU, remote or blocking work was canceled; add isolation, bounded admission and verified cleanup.
- **PT12, training glossary:** Correct after-backward-only DDP glossary wording; ready buckets reduce during backward and completion waits for required reductions. [PyTorch DDP internal design](https://docs.pytorch.org/docs/main/notes/ddp.html#internal-design). Lesson tas-f4 and practice tas-a3 were already qualified.

## Editorial observations for coordinated follow-up

Independent AI cross-review supplied four further defects, verified and corrected by the ML owner:

- **M12, mot-0:** Apply the counter-reset qualification to the glossary as well as mot-f8. [Prometheus metric types](https://prometheus.io/docs/concepts/metric_types/).
- **M13, mot-a3:** The prompt already includes an offline quality comparison, contradicting the model/rubric claim that all checks assess only system health. Distinguish offline evaluation from delayed production outcomes in both fields.
- **M14, ro-a1:** Widening a fallback is not unconditionally valid; require validated, authorized scope and a permitted reject/halt option.
- **M15, mfe-f6:** Lower temperature concentrates token probabilities but guarantees neither safety nor correctness. Replace the promised safety/quality association with distributional behavior and separate evaluation.
- **M16, tas-0:** Scope the 153 FLOPs/byte roofline crossover to the A100 80GB SXM dense FP16/BF16 tensor-core specification: 312 TFLOPs/s divided by 2,039 GB/s. Other precision, sparsity and hardware variants differ. [NVIDIA specifications](https://www.nvidia.com/en-us/data-center/a100/), verified by coordinator and this reviewer.

The public-pack control reading purposes say “Skip anything with an equation” and “Do not study it”, while the chapter correctly allows formal depth when risk warrants it. The MPC reading purpose identifies the name merely with forecast/optimize/re-solve, which is weaker than the chapter's required state model and receding horizon. The bandit reading purpose claims it covers “most real business decisions” without evidence. These pack-owned descriptions were reported to the coordinator; this scope's core-only override does not modify them.

Several previously audited lessons (for example tas-f1/f3/f4/f7 and dle-f4) are short qualifications rather than full worked tutorials. They are accurate enough to retain in this narrow correction. External chapter resources provide deeper study, but this is an editorial limitation, not a full teaching-quality endorsement.
